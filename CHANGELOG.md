# Changelog

Notable changes to DisasterWatch, newest first. Back to the [README](README.md).

**2026-11-08**
- README rewritten as a short project overview with new screenshots and a demo video; the step-by-step setup moved to `docs/quick-start.md` and the public API notes to `docs/api.md`. The code is now under the MIT licence.
- News, Turkish headlines and side stories: Turkish place names match with their case endings, because GDELT drops the apostrophe ("Japonyada", "Türkiyeye"). A piece looking back at a past disaster ("yıl dönümü", "deprem sonrası kurulan", "anniversary", "years after") is dropped in every language unless its headline reports a new event or it is linked to a current feed event.
- News relevance: titles of shows and figures of speech no longer pass as disaster news, in all six languages (musicals, films, "landslide victory", "like an earthquake", "row erupts", team names). A headline that reports impact, a disruption or the hazard acting is kept.
- News country and region filters work for GDELT: an article that matches no feed event is placed by its headline when the headline names exactly one country, in the article's own language. Headlines naming two countries, demonyms, ambiguous names and seas such as "Gulf of Mexico" leave it unlocated. Cached articles are placed at once.
- Multi-source fusion, step 7: news in English, Turkish, Spanish, French, German and Portuguese from GDELT, still one request per refresh. Articles in other languages must name a strong hazard term of their own language. Every article keeps its language and the publisher's country. `GET /news` filters by `lang` and `country` and counts the languages. The news panel gets a language picker, and cards name the language and the publisher's country. The `NewsCache` table gets two nullable columns ([Operations](docs/operations.md)).

**2026-11-07**
- Multi-source fusion, step 6: on the map, marker size shows priority and the outline shows confidence (solid, dashed, dotted), with a legend, tooltip and screen-reader text. The feed filters by minimum priority and confidence and sorts by priority. The event drawer's "Why these scores?" lists every term and each source checked. The dashboard feed carries compact `scores`, and the API page gets an example with the new filters. On a phone, the feed toolbar puts the search on its own row. The API page visual test captures the page, not the window, so it no longer flakes.
- Multi-source fusion, step 5: public API v1 events carry `sources`, `ambiguousSources`, `confidence` and `priority` after the original fields (unchanged, contract-tested); new filters `minConfidence` and `minPriority`; `meta.confirmingSources` and `meta.scoreVersion`; attribution lists EMSC, NOAA NHC, NASA FIRMS and GeoNames.
- Multi-source fusion, step 4: open confidence and priority scores (0–100) with every term returned; exposure from the GeoNames `cities5000` gazetteer (CC BY 4.0), downloaded when the Docker image is built. README section "Scoring methodology" and [Scoring](docs/scoring.md) sections 2–4.
- Multi-source fusion, step 3: cross-source matching (EMSC to USGS quakes, NHC to EONET storms, FIRMS and GDACS to EONET events) with one-to-one, mutual-best and ambiguity rules, roles that tell independent confirmations from relays, and a live evaluation script; [Scoring](docs/scoring.md) documents the rules and the first evaluation (715 of 729 quakes confirmed or listed by EMSC, none ambiguous).
- Multi-source fusion, step 2: NASA FIRMS satellite fire detections near each wildfire (10 km, 48 h), looked up in the background once an hour per fire; off until `FIRMS_MAP_KEY` is set.
- Multi-source fusion, step 1: EMSC earthquakes and NOAA NHC active storms are fetched as confirming sources (lazily, cached, incremental for EMSC, with backoff) and reported in `/health`; nothing visible changes yet. [Data sources](docs/sources.md) lists every source with its licence and fetch rate.
- Rate limits count the real client: behind Cloudflare and Render's hops (and the site's /api rewrite) `req.ip` was an internal address that changed per request, so one client was spread over several counters and unrelated clients could share one. The client address now comes from `True-Client-IP` / `CF-Connecting-IP` (verified live that a client cannot forge either) for every limiter.
- Optional public API keys: sign in with GitHub on the API page (no permissions asked; only the GitHub id and login are stored), create, renew or revoke a key shown once and stored as a hash; 600 requests a minute per key, 60 per IP without one. Privacy page explains what is stored and how to delete it. Dependency advisories in body-parser, qs and zod patched.
- Public read-only API v1 (`/api/v1/disasters`, `/api/v1/disasters/{id}`, `/api/v1/types`): filters, cursor paging, ETag/304, open CORS for GET, 60 requests a minute per IP, source attribution in every response, GDACS reduced to its alert level and report link. OpenAPI 3.1 document with contract tests, and an interactive API page (`/api`, Swagger UI loaded only there). Earthquakes now cover 30 days like the other types (USGS monthly feed); alert ingestion keeps the weekly feed.
- Map cluster icons never cover one another (WCAG 2.5.8 target size); the dashboard, event drawer and news panel load as separate chunks.
- Full frontend audit (write flows on a local stack, read-only flows live, design review at 1440 px and 390 px, axe and Lighthouse): the Alert center and admin forms label every field and the admin page has a main landmark; feed rows name their visible text in order (WCAG 2.5.3); the session check no longer logs a 401 (`GET /users/session`); the Alert center no longer jumps while the session is checked; the phone header keeps to two rows when signed in; news tags no longer repeat the type; the bell says "1 unread notification"; the disabled e-mail switch says why; the basemap host is preconnected; the local nginx proxy survives a recreated backend; CI actions on Node 24. New local write-flow and live read-only test suites.
- Feed ids no longer collide: the 32-bit hash gave five pairs of earthquakes in one week the same id, so the list showed wrong rows after paging and a click could open the other event; ids are now a 53-bit hash of `source:sourceId`.
- Event drawer data: the nearest place of an earthquake (from the USGS place), the countries GDACS lists for wildfires and floods, a storm's development chart (EONET advisory series), and GDACS impact figures (people in the affected area, reported casualties and damage) from the new `GET /disasters/impact`; each shows "unknown" when the source does not publish it.
- The drawer's severity scale reads the thresholds the backend serves with the feed (`severityRules`); the frontend copy is gone.
- Map focus: "Zoom to" (now "Show on map"), the news panel's "Show on map" and a click on a Today's events card fly the map to the event even when the marker caps (15 strongest quakes, wildfires per country) or the type filter had left it off the map; on a phone they switch to the Map view. A news link to an event the feed no longer has says so instead of waiting silently.
- Event drawer rewritten for readers: a one-sentence summary, key facts, the severity scale with the event's level and the rule's thresholds, plain-language context (USGS magnitude and depth classes, Saffir-Simpson category, GDACS level meaning, how long the source tracked the event) and nearby events; raw values moved to a folded "Technical details" section. Frontend only, from the data the feed already carries.
- Today's events cards open their event; the signed-out Alert center is centred like the other single-column pages; the map tooltip's pointer is a triangle again (all four borders were coloured, which drew a square).
- Visual regression and accessibility tests (Playwright, axe-core) for every page at 1440 px and 390 px, in CI.

**2026-10-26**
- Scheduled wake-up: `POST /internal/ingest` answers within 60 seconds (202 while a long run goes on, the workflow follows it on `/health`); the ingestion job rates only the EONET events it has not recorded yet instead of refreshing every lookup of the last 30 days. Every backup run that cold-started the backend had failed on a 90-second timeout before.
- Scheduler: GitHub's scheduled workflow is the only wake-up (the external cron service was dropped: Render's edge refused its requests to a sleeping service, `hibernate-wake-error`); it runs every few hours in practice, so the Alerts page and this README say that alerts can be hours late. The e-mail channel counts as "unknown" after 12 hours without a report (was 3).

**2026-10-23**
- The public feed no longer waits for GDACS after a restart: known levels come from the new `GdacsCache` table, missing lookups finish in the background. First `/disasters` after a cold start, measured locally: 257 s before, 4–8 s after (bounded by the EONET download).
- Earthquakes: USGS weekly M 4.5+ feed (was the last 24 hours), the same window as the rest of the feed; the map's earthquake cap and a full feed page keep the strongest quakes.
- README brought up to date for the first public version: live link, architecture, methodology summary and the limits of the free setup and of the sources.
